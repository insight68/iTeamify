
本文介绍自研项目 Findyn：把「找客户 → 写开发信 → 自动发送 → 盯回信」做成 7×24 小时全自动流水线。后端基于 FastAPI + LangGraph 搭建多 Agent 状态机，模型层统一封装 LiteLLM 支持热插拔切换，任务持久层采用 PostgreSQL 双层队列，进程重启不丢失任务数据。

一、系统整体架构
Findyn 三层分层架构：
前端 Frontend
基于 React + Vite 开发，六大核心功能模块：任务看板、队列任务、挖掘结果、邮件营销、新建任务、系统设置。
后端 Backend
FastAPI 提供 REST 接口 + SSE 实时推送，业务核心是 LangGraph 状态流转图。
基础设施
PostgreSQL：统一存储任务、邮件记录、LangGraph 状态快照（checkpointer）
可选 Langfuse：用于 LLM Token 用量、调用成本观测
完整数据流
React 前端 → FastAPI 服务 → LangGraph 流水线
流水线 Agent 链路：
InsightAgent → KeywordGenAgent → SearchAgent → LeadExtractAgent → Evaluate 评估节点
模型统一由 LiteLLM 调度，对接 OpenAI/DeepSeek/NVIDIA NIM 等大模型；
搜索依赖 Tavily/Serper，网页解析依赖 Jina Reader；
所有数据落地 PostgreSQL，前端通过 SSE 实时接收任务状态。
二、核心设计 1：LangGraph 多 Agent 闭环流水线
客户挖掘主链路基于 LangGraph StateGraph 构建闭环状态机，5 个 Agent 分工协作：
InsightAgent：理解我方公司、产品、核心卖点，输出业务定位
KeywordGenAgent：反向推导目标客户画像，批量生成海外搜索关键词
SearchAgent：聚合 Google、Google 地图、海外 B2B 平台站内搜索，批量获取企业官网
LeadExtractAgent：自适应抓取官网 / 列表页 / 资讯页，结构化抽取邮箱、电话、WhatsApp、LinkedIn 等线索；域名去重避免同企业重复调用 LLM，大幅降低成本
Evaluate 评估节点：判断当前线索池是否充足，决定「继续挖掘」或「进入邮件营销环节」
流转分支：评估通过则循环回到搜索环节；评估终止则进入 EmailCraft 模块，批量生成多语种开发信序列。
三、核心设计 2：双模型分离 + LiteLLM 统一适配
LLM 调用按职责拆分两类，独立限速、独立选型，通过 LiteLLM 统一接入，一键切换厂商：
推理模型（ReAct 决策）
负责复杂逻辑判断：是否继续挖掘、页面抓取策略、线索质量打分等强思考场景。
生成抽取模型
负责结构化信息抽取、开发信多语种生成、文本改写等常规任务。
支持的大模型厂商：OpenAI、Anthropic、OpenRouter、Groq、GLM、Moonshot、MiniMax、DeepSeek、NVIDIA NIM 等。

四、核心设计 3：两层 PostgreSQL 持久化队列
系统不依赖 Redis / 第三方 MQ，直接使用 PostgreSQL 实现高可靠持久队列，保障 7×24 小时稳定运行。
第一层队列：jobs（客户挖掘任务队列）
调度器写入待挖掘任务；
后台执行者领取任务，完整执行全链路挖掘流程，任务状态实时入库；
进程崩溃、重启后自动恢复未完成任务。
第二层队列：email_messages（邮件发送队列）
挖掘完成后批量生成跟进邮件序列存入本表；
邮件规划器每 60 秒轮询，按外贸合规频率限频发送；
后台持续监听 IMAP 邮箱回信，一旦收到客户回复，自动终止该客户全部后续跟进邮件。

五、两大差异化业务亮点

1. WhatsApp 联系方式识别 + 一键直链
   系统专门优化海外社媒联系方式解析：
   自动识别页面内 wa.me 短链、纯数字手机号、标注式 WhatsApp 号码；
   统一归一化为带国家编码标准数字；
   自动生成 https://wa.me/国家码手机号 直达链接，方便外贸即时触达。
2. 按目标市场自动切换邮件语种
   在线索抽取阶段根据企业域名、地址预判断市场，提前锁定邮件语言，无需额外 LLM 推理开销：
   西语市场（西班牙、墨西哥、秘鲁、智利等）→ 西班牙语 es
   葡语市场（巴西、葡萄牙）→ 葡萄牙语 pt
   其余欧美 / 东南亚市场默认英语 en
   系统支持导出外贸标准 CSV 表格，包含 WhatsApp 链接、LinkedIn 直达链接、客户匹配优先级、质量评分等字段，可对接邮件群发工具批量触达。

七、项目总结：AI 自动化系统三大工程取舍
LangGraph 状态图标准化复杂业务流程
多 Agent 各司其职，流程闭环、节点可监控、可重试，把零散的 AI 能力串联成完整业务流水线。
LiteLLM 解耦业务与大模型厂商
推理 / 生成两套模型分离调度，独立限速，随时切换低成本模型，适配不同预算场景。
数据库持久队列是长期稳定运行核心
两层 PostgreSQL 队列解决任务丢失、定时邮件调度问题，比单纯堆叠更多 Agent 更具备工程落地价值。
面向外贸 B2B 海外获客场景，整套系统实现线索挖掘、邮件自动化全链路无人值守，把重复找客户工作交给 AI，人工只聚焦客户成交谈判。
