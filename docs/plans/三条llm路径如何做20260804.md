## 重点分析：openagent 架构与 prospector 的关系

### openagent 架构设计

openagent 是 iTeamify daemon 的**第 18 个 agent backend**，与其他 17 个（claude/codex/copilot/cursor/...）实现同一个 `Backend` interface。它的特殊性在于：

1. **进程内嵌**：不 spawn CLI 子进程，直接在 daemon 进程内跑 Open Agent SDK 的 agent loop（32 个内置工具 + MCP + permissions + hooks + cost tracking）。这意味着用户机器不需要预装 claude/codex 等 CLI binary。
2. **provider-agnostic**：daemon 调度链（`agent.New → backend.Execute → drain loop`）完全 provider-agnostic，只要 backend 正确产出 `Message/Result` 流，idle watchdog、task usage 上报、取消语义全部复用。
3. **LLM 调用**：模型 API 由 SDK 的 `api.Client` 远程调用，daemon 透传 `Config.Env`（含 `CODEANY_API_KEY` / `ANTHROPIC_API_KEY` / `CODEANY_MODEL`）。
4. **取消/超时**：直接靠 `ctx.Cancel()`，无需 SIGTERM→SIGKILL 进程组。
5. **MCP**：`opts.McpConfig` JSON 解析为 `map[string]types.MCPServerConfig`，SDK 在 `Init()` 阶段连接，无需写临时文件传 `--mcp-config`。
6. **权限**：`PermissionModeBypassPermissions`——daemon 层已做权限控制，SDK 内 bypass 避免双重审批。

### openagent 如何调用 LLM

openagent **本身不直接调 LLM HTTP API**——它构造 `sdkagent.Options{Model, CWD, SystemPrompt, MaxTurns, TimeoutMs, Env, MCPServers, Effort, PermissionMode}`，调用 `sdkagent.New(opts).Init(ctx).Query(ctx, prompt)`，由 SDK 内部的 `api.Client` 完成实际模型调用。daemon 只消费 SDK 产出的事件流（`MessageTypeAssistant` / `tool_result` / `MessageTypeResult`），累积 token usage 到 `map[model]TokenUsage`。

### openagent 与 prospector 的 Python LangGraph 是否有功能重叠

**结论：没有功能重叠。两者是完全不同维度的系统。**

| 维度               | openagent (Go)                                  | prospector (Python LangGraph)                                                        |
| ------------------ | ----------------------------------------------- | ------------------------------------------------------------------------------------ |
| **定位**     | 通用 coding agent runtime（18 个 backend 之一） | 52tuan.com Phase 1 B2B 客户挖掘专用 pipeline                                         |
| **执行模型** | 单轮 agentic loop（SDK 自带 32 工具 + MCP）     | 5 节点固定流程 StateGraph（Insight→KeywordGen→Search→LeadExtract→Evaluate）      |
| **LLM 调用** | Open Agent SDK 的`api.Client`（远程模型 API） | `litellm.acompletion`（双模型：reasoning + extraction）                            |
| **工具能力** | 文件读写、bash、MCP 等 32 个内置工具            | 无 agentic 工具，只有 LLM 推理 + HTTP 搜索/Jina Reader                               |
| **任务来源** | iTeamify task queue（daemon 调度）                | prospect_jobs 表（Go 后端 ClaimJob）                                                 |
| **输出**     | 代码修改 / 文本回复                             | 结构化 leads（公司名/域名/邮箱/电话/WhatsApp/LinkedIn/质量分）                       |
| **恢复机制** | 第一版不持久化 session                          | PostgresSaver checkpoint，`thread_id = job.id`                                     |
