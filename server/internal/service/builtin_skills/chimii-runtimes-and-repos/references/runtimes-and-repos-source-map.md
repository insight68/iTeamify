# Runtimes and repos source map

- `server/cmd/iteamify/cmd_runtime.go` registers `runtime list`, `usage`, `activity`, `update`, and `delete`.
- `runtime list` reads `/api/runtimes` and prints `id`, `name`, `runtime_mode`, `provider`, `status`, and `last_seen_at`.
- `runtime update` posts to `/api/runtimes/{runtime-id}/update`; with `--wait` it polls update status. Initiation enforces runtime-owner or workspace-owner/admin access through `canEditRuntime`; status polling additionally permits that request's immutable initiator so an in-flight poll survives an admin-role change (`server/internal/handler/runtime_update.go` and `runtime.go`).
- `runtime delete` deletes `/api/runtimes/{runtime-id}`; with `--cascade`, it first reads the `runtime_has_active_agents` conflict payload and posts those ids to `/api/runtimes/{runtime-id}/archive-agents-and-delete`.
- `server/cmd/iteamify/cmd_repo.go` registers `repo checkout <url> [--ref]`.
- `repo checkout` requires `ITEAMIFY_DAEMON_PORT`, sends `workspace_id`, `workdir`, `ref`, `agent_name`, `task_id`, and the daemon-managed optional `checkout_mode` to local daemon `/repo/checkout`, then prints the checked-out path.
- `server/internal/daemon/health.go` resolves the checkout ref: request `ref` wins; otherwise it asks `server/internal/daemon/daemon.go` for the current task's project repo default ref. It forwards the validated isolated-checkout mode into `repocache.WorktreeParams`.
- `server/internal/daemon/daemon.go` injects `ITEAMIFY_REPO_CHECKOUT_MODE=isolated` only for Linux Codex tasks. `server/internal/daemon/repocache/cache.go` implements that mode as a same-filesystem local clone with task-local Git metadata and the real repository as `origin`; other runtimes keep the linked-worktree path.
- When the bare cache is a partial clone, that isolated checkout must have `remote.origin.promisor` / `partialclonefilter` restored before its first `checkout`: `git clone --local` neither inherits them nor errors on the missing objects it leaves behind, so the checkout would otherwise succeed with an empty working tree. The linked-worktree path shares the cache's own config and needs no such repair.
- `server/cmd/server/router.go` registers daemon APIs under `/api/daemon`, including workspace repos and task claim.
- `server/internal/daemon/daemon.go` claims tasks, prepares workdirs, launches provider CLIs or the embedded OpenAgent backend, and reports completion.
- `server/runtime/agent/loop.go` drains model streams, emits deltas and tool results, records usage on every exit, and checkpoints complete rounds. `server/pkg/agent/openagent.go` maps explicit stop reasons to outcomes and persists session snapshots through `openagent_session.go` before publishing resume pointers.
- `server/internal/daemon/task_reports.go` stores pending task receipts under `.task-reports`, scoped to server and daemon identity. Startup replays receipts after auth renewal and protects tasks with pending terminal results via the optional `protected_task_ids` field of the recover-orphans request (`server/internal/handler/task_lifecycle.go`). Runtime retries use the same message sequences and cumulative usage; they never invoke the agent runner.
- `server/internal/handler/daemon.go` accepts message batches transactionally under a task-row lock, treats identical sequence/content replays as acknowledgements, rejects conflicting content, and broadcasts only newly committed messages. `server/internal/daemon/gc.go` preserves workdirs referenced by pending receipts.
- `server/internal/daemon/execenv/runtime_config.go` injects task/project/repo context into agent workdirs.
