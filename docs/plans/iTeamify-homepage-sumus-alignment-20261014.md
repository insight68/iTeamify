# iTeamify 营销首页优化方案（参照 sumus.im）

- 日期：2026-10-14
- 目标页：`apps/web/app/(landing)/page.tsx` → `features/landing/components/iteamify-landing.tsx`
- 参照对象：https://sumus.im/
- 配套交付物：`docs/plans/iTeamify-homepage-sumus-alignment-对照预览-20261014.html`（自包含单文件，`file://` 直接打开）
- **本次只出方案，没有改动任何产品代码**

---

## 0. 结论

1. **首页「AI 模板感」的 80% 来自一行字体**：H1 是 `Inter 500` / 58px 的无衬线粗体，而参照对象 sumus.im 用的是 `Libre Baskerville 400`（衬线细体）。其余是底色（浅蓝 `#f0f5fb`）、CTA 权重（两个同重按钮）、以及 36 个 1px 描边卡片堆出来的"表格感"。
2. **我们不需要"抄" sumus.im —— 我们自己的服务详情页早就是那套调性了**。`/features/project-delivery` 的 H1 实测是 `Source Serif 4 / 450 / 70px`，与 sumus 同方向的衬线细体。**首页是站内唯一没接上这套语言的地方**，这使改动从"引入新设计"降级为"修一处不一致"。
3. **结构上有一处确定的冗余**：`scale` 区块的 items（Squads / Autopilots / Skills）是 `capabilities` 区块 items 的真子集，同一份能力在页面上写了两遍，两屏相隔 1200px。合并后页面从 11 个区块降到 8 个。

**推荐路径：先做 P0（纯视觉，零内容风险），再按 D1 的拍板决定是否进 P1（结构收敛）。**

### 1.1 方法

两个必须注意的坑（取证时踩过）：

- 营销页内容在**内层滚动容器** `.landing-brand.landing-light.h-full.overflow-y-auto` 里，`html/body` 是 `overflow:hidden`。用 `document.scrollingElement.scrollHeight` 量会得到 `900`（只有一屏），必须找到真正的滚动容器再驱动它，否则分段截图全是同一屏。

### 1.3 两个必须记下的技术事实

1. **首页接上衬线是零成本的。** 运行时 `--font-serif` 解析为
   `'Source Serif 4', 'Source Serif 4 Fallback', ui-serif, ...`，且 `document.fonts` 显示 Source Serif 4 **已加载**（服务页在用）。
   首页的 `.mh-h1` / `.mh-h2` 没有声明 `font-family`，直接继承 body 的 `--font-sans`（Inter）——**这是首页与服务页唯一的字体分歧点**。
   顺带发现一个隐患：`packages/ui/styles/tokens.css:6` 是 `--font-serif: var(--font-serif);`（自引用无效声明），真实值由别处注入。建议顺手清掉，否则以后有人改这行会静默失效。
2. **首页样式是隔离的，改动不会牵连服务页。** `home-marketing.css` 头部注释明确写了它与 `service-marketing.css` 解耦，token 声明在 `.mh-home` 上。**P0 可以放心做完，不影响任何服务页。**

## 2. 诊断：AI 感是怎么来的

对照 sumus.im，问题不是"不够高级"，而是三个机制的叠加：

### 机制 1：无取舍的全量覆盖（11 个区块 / 6.3 屏）

`capabilities` 已经写了 Squads / Autopilots / Skills，`scale` 又把这三样单独写了一屏。这不是"更全面"，是让读者在第二屏看过的东西、第五屏再看一遍，从而判定"这页在凑内容"。

### 机制 2：等高重复的骨架

11 个区块里有 9 个共用同一套骨架：**小标签（蓝 12px 大写）→ H2（43px/550）→ 灰色 lead（16px）→ 一排内容**。实测 11 个 H2 的计算样式完全一致。

真正的后果是**没有强弱之分**：讲"智能体是负责人，不是插件"（核心差异）和讲"我们的 FAQ"（次要收尾）用同一个字号、同一个留白，读者没有节奏指引。

对比 sumus：H2 只有两档（48 大节 / 36 feature），且**所有 feature 标题同一档、同一衬线**——它靠"每屏只讲一件事 + 大量留白"制造节奏，而不是靠字号差。

### 机制 3：用"卡片"代替"证据"

36 个 1px 边框 + 14px 圆角的元素，把每一句话都装进同一个盒子里。sumus 的做法相反：**去掉盒子，用真实产品截图当证据**（22 张），靠阴影浮起、靠留白分区。

具体到首屏：我们的三栏看板是**纯 CSS 复刻**的假界面（`mh-card` / `mh-avatar` / `mh-status-live`）。它设计上不丑，但一眼能看出是"设计稿"——而首屏恰恰是最需要可信度的地方。

## 3. 分层方案

按「改动归属」切，不按重要性切。

### P0 · 纯视觉收口（可立刻做完，零内容风险，零回归面）

只动 `apps/web/features/landing/home-marketing.css`，**不动任何 `.tsx`，不动 i18n 字典**。

| # | 改动 | 现值 | 目标值 | 依据 |
|---|---|---|---|---|
| P0-1 | H1 字体 | 继承 Inter | `var(--font-serif), Georgia, serif` | 与服务页 `.service-detail-hero h1` 一致 |
| P0-2 | H1 字重 | 500 | **450** | 服务页实测值 |
| P0-3 | H1 字距 | `-0.02em` | `-0.045em` | 服务页实测值；衬线需要更紧的字距才不散 |
| P0-4 | H2 字体 | 继承 Inter | `var(--font-serif), Georgia, serif` | 同上 |
| P0-5 | H2 字重 / 字距 | 550 / -0.015em | **450 / -0.035em** | 同上 |
| P0-6 | hero 底色 | `#f0f5fb`（浅蓝） | `#fff` | 去掉"色块 hero"，改用留白分隔（sumus 全站白底） |
| P0-7 | hero 高度 | `padding: 74px 0 86px` | `96px 0 0`（视觉下沉，接看板） | sumus hero 1282px 含产品图，靠留白撑 |
| P0-8 | 次 CTA | 白底 1px 描边按钮 | 去边框，改文字链接 + 下划线 | 两个同重按钮互相稀释；sumus 只有 1 个主按钮 |
| P0-9 | 卡片描边 | 36 个元素带 `1px solid #dbe5ee` | `mh-cap` / `mh-audience` / `mh-card` 去边框，改阴影或无框 | 机制 3 |
| P0-10 | 最小字号 | 9px | **≥12px**（13 档收到 9 档以内） | sumus 最小 12px；9px 只出现在卡片 meta 与面板标签 |
| P0-11 | 圆角档位 | 10 / 12 / 14 / 999 / 50% | **8 / 16 / 999** | 收口圆角语义 |
| P0-12 | 区块底色 | `mh-sec--tint` 交替浅蓝 | 全部白底，改用 1px 分隔线或纯留白 | 交替底色是最典型的模板特征 |

预期收益：观感收益的大头（字体 + 底色 + 去描边）。**风险：接近零**——`home-marketing.css` 不与服务页共用，且不触碰数据。

**只做 P0 会留下的问题**：11 个区块的冗余还在（`scale` 与 `capabilities` 重复），页面依然偏长，"凑内容"的观感只解决一半。

### P1 · 结构收敛（需要改 i18n 字典，中英两套 + 3 个测试）

| # | 改动 | 说明 |
|---|---|---|
| P1-1 | 删 `scale` 区块 | 它的 3 项是 `capabilities` 的真子集，内容并入能力矩阵 |
| P1-2 | 合并 `pains` + `comparison` | 两者都在讲"现有方式不够用"（pains 讲症状、comparison 讲竞品），合并成**一张对照表** |

| P1-6 | `audiences` 4 卡 → 2×2 或一行标签 | 4 栏在 1240px 下每栏仅 290px，正文挤成 3 行 |

## 5. 验收标准（可量化，改动后逐条复核）

1. 首页与 `/features/project-delivery` 的 **H1 计算字体族、字重、字距逐项相等**（`getComputedStyle` 取值比较，不靠肉眼）；
2. 字号去重集合 **≤ 9 档，最小 ≥ 12px**（现状 13 档 / 最小 9px）；
3. 首页 `main > section` **≤ 8**（现状 11），页面高度 **≤ 4800px**（现状 5707px）；
4. 带 1px 边框的元素 **≤ 12 个**（现状 36 个）；
5. 首屏在 1440×900 与 390×844 下均能露出**至少 1 条完整内容**（现状移动端需滚动才见内容）；
6. 375 / 390 / 414 三宽度下 `scrollingElement.scrollWidth === clientWidth`（现状已通过，不得回归）；
7. `<h1>` 数量恒等于 1；`<main>` 数量恒等于 1；
8. `pnpm typecheck` + `pnpm test` + `make check` 干净。
