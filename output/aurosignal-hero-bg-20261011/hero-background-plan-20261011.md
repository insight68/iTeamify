## 二、参照图解剖（1920×767，比例 2.50:1）

四个图层，其中三个可直接用代码复刻：

1. **左 45%｜产业证据簇** —— 三条**斜切照片条**（厂房 / 城市 / 港口）。要点：不是"圆角卡片"；左端**被画布切掉**，右端**渐隐融进白色**，照片是半透明的、泡在白色缎带里；条与条之间用**虚线 + 蓝色节点**串起来。
2. **中 21%｜留白 + 日出暖光** —— 全图唯一的暖色，也是唯一留给标题的位置。
3. **右 34%｜地球** —— 夜光卫星风格。**关键一手**：圆心 (1594, 411)、r≈368，**从右下被裁掉**（右边缘 1962 > 1920，下边缘 779 > 767）；上左边缘**融进天空、没有硬边**，表面叠加光轨与节点网络。
4. **底部｜两层白色缎带**，横贯全宽，从右向左扫。

→ 可迁移的是 1/3/4 的**结构**与 2 的**暖冷对比**；照片本身才是必须用位图的部分。

## 三、三条硬约束（决定"不能照搬"）

### 3.1 画幅不匹配（算术）

把 1920×767 以 `background-size: cover` 铺进 1440×900：

```
scale = max(1440/1920, 900/767) = max(0.750, 1.174) = 1.174
渲染尺寸 = 2254 × 900  →  水平溢出 814px  →  左右各裁 407px
换算回原图：左右各裁 407 / 1.174 ≈ 347px
```

结果：

| 元素 | 原图范围 | cover 后 | 结论 |
|---|---|---|---|
| 左侧三条照片条 | x 0–430 | 可见区从 x 347 起 | **约 80% 被裁掉** |
| 地球 | 圆心 x 1594 | 可见区止于 x 1573 | **整个被裁掉** |

即：铺满之后拿到的**恰好是这张图信息量最低的中间天空**。390×844 更极端（scale 1.10，可见区只剩原图宽度的 **19%**）。

### 3.2 首屏有两个主角

首屏的主角是中间那个 1240×718 的**产品窗口**（信息密度极高）。参照图是"整张即产品"的海报。整张铺满 ⇒ fold 变成"海报 + 截图"两层互相抢焦点，同时窗口下方 78% 的画面看不到。

### 3.3 蓝不是我们的蓝

参照图的蓝落在企业蓝区间（约 `#1f5fa8`–`#5b9bd5`）；品牌三色是 `--service-brand-cyan #00b0ff` / `--service-brand-blue #0043ff` / `--service-brand-violet #6d22f8`，主按钮 `--service-accent #165de5`。直接引用会出现**两套蓝**，必须整体调色（去饱和 + 色相拉向品牌蓝）。

## 四、方案 A（推荐）· 逐文件改动清单

只动两个文件，**不动 `iteamify-landing.tsx` 的结构**（`ServiceHeroArtwork` 仍是 `.service-hero` 的第一个子元素）。

### A1 `apps/web/features/landing/components/service-shared.tsx`

重画 `ServiceHeroArtwork()`（现在第 212–319 行），viewBox 保持 `0 0 1600 720`（或改 `0 0 1440 720`，与 CSS 的 `max(100%,1440px)` 对齐）：

1. **左翼证据条 ×3**（新）—— 位于 x 0–330。每条：`skewX(-8)` 的圆角矩形，左端出画（`x=-40`），右端用 `linearGradient(#fff 0→1)` 覆盖实现渐隐；内容两行：`STEPSTONE.DE` / `招聘：注塑件采购工程师`（与 `SignalPreview` 的示例来源保持一致，避免"两套示例"）。垂直位置 y ≈ 24 / 110 / 196。
2. **节点 + 虚线**（新）—— 三条条右端各一个 `r=5` 品牌蓝节点（x≈300/288/276），节点间用 `stroke-dasharray="2 5"` 竖直虚线相连；再由上方两个节点用 `stroke-dasharray="3 7"`、`opacity .22` 的弧收束到地球左缘，**弧线全程控制在 y < 60**，避免压到标题。
3. **地球改法**（改现有）—— 圆心从 `(1450, 250) r=304` 移到 **`(1352, 148) r=272`**：右缘 1624 > 1440 ⇒ **右下出画**。**删掉外圈 `stroke` 的整圆描边**，改为：
   - `radialGradient` 大气层（cyan 6% → blue 6% → violet 2%）；
   - `clipPath` 内画大陆点阵 + 经线椭圆 + 纬线弧；
   - clip 内叠一层 `linearGradient` 白色 → 透明（from 左上到右下）把**上左边缘洗掉**，让边缘融进天空。
   - 只保留一条 `rx=332 ry=112 rotate(-28°)` 的轨道椭圆做"光轨"。
4. **缎带 ×2**（新）—— 从左右两侧向窗口上沿（y≈290）合流：`stroke-width 30 / opacity .07` 的粗底 + 同路径 `stroke 1.3` 的细线（`linearGradient` cyan→blue→violet）。
5. **暖光**（新）—— `radialGradient` 于 `(760, 190)` 半径 560×400，`#ffcf9e` opacity .16（实际叠加后约 6%），放在所有图层之下。
6. **移动端 `service-atlas-mobile`**（改现有）—— 保持 `viewBox 0 0 600 440`，重画为：**两条单行证据条**（y≈250 / 292，宽 266、高 30）+ 一个节点 + 一段弧连向上方地球一弧。取代现在两条弧 + 两个 `r=17/10` 的圆。

### A2 `apps/web/features/landing/service-marketing.css`

- `.service-hero-home::before`：在现有两层 radial 之上插一层暖光
  ```css
  radial-gradient(ellipse at 50% 8%, color-mix(in srgb, #ffcf9e 7%, transparent), transparent 46%),
  ```
- `.service-atlas-desktop`：`height: 640px` 维持（地球新位置在其内），检查 1100px 断点下的 495px 缩放是否仍让地球落在窗口右侧（见验收 4）。
- `.service-hero-home` 的暖色必须先过 `prefers-contrast: more`：在该媒体查询里把暖光层去掉（现在只有 `--auro-muted` / `--auro-line` 两个变量，需补一条 `.service-hero-home::before{background:…}` 覆盖）。

### 验收断言（可量化，逐条可测）

1. **标题对比度不降**：首屏文案带（页面 y 141–321）在 1440×900 下的背景像素采样，`h1` 前景 `rgb(16,44,70)` 与背景最大亮度差对应的对比度 **≥ 10:1**（现状约 12:1）。
2. **零位图**：`document.querySelectorAll('.service-hero img').length === 0`（现状即 0，方案 A 必须仍为 0）。
3. **无溢出**：1440 / 1100 / 390 三宽度下 `document.scrollingElement.scrollWidth === clientWidth`（注意本页真正的滚动容器是 `.landing-brand`，同时校验它）。
4. **移动端不再出现"无主语"装饰**：390×844 下 `.service-atlas-mobile` 内至少 2 个 `<text>` 节点，且其包围盒与 `.service-hero-copy` 的包围盒**不相交**（允许 ≥8px 间距）。
5. **既有门禁不破**：`pnpm typecheck`、`next build`、以及 `apps/web/app/homepage-performance-boundary.test.ts`（它断言着陆页无 `use client`、无 `auro-rise`、无 `will-change`、`landing.css` 有 `prefers-reduced-motion`）全部通过。
6. **可关掉动效**：新增的动画（如有）只写在 `@media (prefers-reduced-motion: no-preference)` 里，与现有 `.service-atlas-trace` / `.service-atlas-pulse` 一致。

### 风险

- **SVG 表达力上限**：拿不到照片的"真实感"。这是方案 A 明确让出的东西。
- **左侧条的文案与产品内示例耦合**：条里写的是真实证据文案，必须与 `SignalPreview` 的示例（`stepstone.de` / `saechsische.de` / `kessler-geraete.de`）同源，否则首屏出现"两套示例"。
- **缎带没有展开空间**：窗口从 y=290 起吃掉中间整块，缎带只能在左右各 100px 的侧带里露一角。要它横贯全宽必须先动窗口（D3）。
- **暖色会轻微改变品牌观感**（纯冷 → 暖冷对比），需 D4 点头。

方案 A 的全部结构 + 左翼三条条换成 3 张真实照片（厂房 / 城市 / 港口）。

- 预览页里已经用参照图左簇的真实像素演示过：缩到 1440 宽后三条条落在 y 81–500，**第三条（港口）整条落在窗口后面**，首屏只看得见前两条半。

- 定性：这是**换材质**，不是换方案。建议 A 上线稳定后再做，不要和 A 混在一个 PR 里。

### C · 整张位图 cover（不推荐）

- §3.1 已给出算术：左右各裁 347px，左簇损失 80%、地球全丢。
- 还要额外加 ≥60% 白幕才能保住标题对比度 —— 等于把照片又压回半透明。
- 首屏最大资源从"文字"变成"1 张 1920 宽位图"，而现状是 **0 图片**。
- 定位冲突：整站口径是「不卖联系人名单，也不保证成交」，一张通用"地球 + 集装箱"背景正是外贸站最模板化的那一层。
