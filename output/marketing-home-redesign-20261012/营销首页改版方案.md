# 营销首页改版方案 · 新一代小团队协作系统

日期：2026-10-12
目标：把营销首页从「外贸获客系统」重做为「新一代小团队的协作系统」

---

## 0. 结论先行

**改版的核心动作不是换皮，是换叙事轴。**

现有首页讲的是 `See overseas opportunities first.`（外贸买家信号 → 商机 → 报价 → 履约），
但产品和仓库的权威定义是**「人 + AI 协作的任务平台，agent 是一等公民」**：

- `CLAUDE.md:14` — "iTeamify is an **AI-native task management platform for small teams**, with agents as first-class assignees that can own issues, comment, and change status."
- `docs/product-overview.md:73` — "iTeamify 不是一个 AI 工具，而是一个**人 + AI 协作的任务管理平台**。agent 是一等公民，和人在同一个工作流里。"

也就是说：**你要做的定位，就是产品本来的定位。** 现有首页是一次垂直偏移（外贸），
把最独特的能力（agent 当成员用）藏在了「第 5 屏之后的一个小 aside」里。

改版要做的三件事：

1. **把差异化拉到首屏** —— 卖点从「帮你找客户」换成「**AI 是团队成员，和你共用一张看板**」
2. **让产品界面当主角** —— agent 出现在 assignee 下拉里，这一眼比任何文案都有说服力
3. **补上信任层** —— 代码跑在你自己机器上、不锁厂商、可自托管（现有首页完全没有这屏）

## 1. 定位与叙事

### 1.1 一句话定位

| 层级 | 文案 |
|---|---|
| 品类 | 面向小团队的 AI 原生任务协作平台 |
| 主张（H1） | **把任务指派给 AI，就像指派给同事。** / **Assign work to AI like you'd assign it to a teammate.** |
| 展开（副标题） | Agent 出现在你的看板、评论区、订阅列表里——和你共用同一个工作流，跑在你自己机器上，不绑定任何一家模型厂商。 |
| 反面定义 | 不是 copilot，不是聊天框，不是又一个 AI 工具。 |

### 1.2 差异化三角（全页反复打这三点）

这三点全部有代码/文档证据，是真正的护城河，也是竞品无法用一句文案追平的：

**① 同一张看板（Polymorphic Actor）**
所有「谁做了什么」的字段都是 `actor_type(member|agent) + actor_id`。
Agent 能被指派 issue、能创建 issue、能发评论、能当 project lead、能进订阅列表、**甚至有 inbox**（`inbox_item.recipient_type` 支持 agent）。
证据：`CLAUDE.md:243`、`docs/product-overview.md`「多态行动者」词条、`packages/core/issues/ws-updaters.test.ts` 中 `assignee_type:"member"` 与 AGENT_ID 并存。

**② 跑在你自己的机器上（分布式执行）**
Server 只做调度、状态同步、存储；**agent 不在 server 上运行**，而是在用户本机 daemon 拉起的隔离工作目录里执行。
证据：`docs/product-overview.md` 3.5「Runtime 运行时 & Daemon 守护进程」。

**③ 不锁厂商（Vendor-neutral）**
本地 daemon 自动探测 `$PATH` 上的 CLI 并注册为 runtime。支持 14 种：Claude Code · Codex · CodeBuddy · GitHub Copilot CLI · OpenCode · OpenClaw · Hermes · Pi · Cursor Agent · Kimi · Kiro CLI · Antigravity · Qoder CLI · Trae CLI。
证据：`README.md:34`、`docs/product-overview.md` 3.5。

### 1.3 目标人群（小团队定义）

- 3–15 人的产品 / 研发 / 设计团队 —— 有协作需求但没有专职 PM/DevOps
- 独立开发者 + 外部协作者 —— 一个人要当一支队伍用
- AI 原生创业团队 —— 已经在用 coding agent，卡在「管不过来」
- 有 SOP 沉淀需求的团队 —— 用 Skill 把经验变成可复用资产

> 依据：Squads（leader agent 稳定路由）、Multi-Workspace、Self-Host 三个能力都指向「团队」规模，而不是「个人」工具。
> 现有首页的 4 个受众画像（有产能的工厂 / 贸易公司 / 靠复购的出口商 / 外贸 SOHO）应作为 **Solutions 子页**保留或下线，不占首页。

### 2.1 能力矩阵（第 4 屏，6 张卡）

用**人话**写，每条都对应真实机制（不要写成功能名词表）：

| 卡 | 标题 | 一句话 | 3 个要点 |
|---|---|---|---|
| 1 | Agents as teammates | 给 agent 派活，跟给同事派活是一个动作 | 有 profile 和头像 · 出现在看板与评论区 · 会主动报 blocker |
| 2 | Squads | 团队变大了，路由不用改 | 指派给 `@FrontendTeam` 而不是某个人 · leader agent 决定谁接手 · 人和 agent 可以混编 |
| 3 | Autopilots | 没人触发，活也照做 | cron / webhook / 手动三种触发 · 自动建 issue 并派给 agent · 内置 6 个模板（日会、周报、依赖审计…） |
| 4 | Reusable Skills | 一次做对，全队会做 | Markdown 写的经验文档 · 注入到 CLI 原生目录 · 挂到 agent 上就生效 |
| 5 | Unified Runtimes | 一块面板看清所有算力 | 本地 daemon + 云 runtime · 自动探测已装 CLI · 实时状态与用量 |
| 6 | Chat & Inbox | 不用为每句话开一个 issue | 和 agent 持久多轮对话 · 会话上下文自动恢复 · agent 也会有 inbox |

### 2.2 对比表（第 8 屏）

| | Cursor / Copilot 这类 | Linear / Jira 这类 | **本产品** |
|---|---|---|---|
| 谁在执行 | 你 + 一个 agent | 只有人 | **人 + 一支 agent 队伍** |
| Agent 有没有身份 | 没有，是 IDE 里的功能 | 不适用 | **有 profile、能创建任务、能被订阅** |
| 团队能不能一起看 | 看不到 | 只能看人的进度 | **人和 agent 在同一块板上** |
| 会不会重复堆工作 | 每次从零开始 | — | **Skill 沉淀 + 会话恢复** |
| 厂商绑定 | 绑一家 | — | **不绑，14 种 CLI 随便换** |
| 数据在哪 | 厂商云 | 厂商云 / 自建 | **agent 跑在你机器上，可自托管** |

> 这张表是转化利器：它把「你已经在用 AI 了」的人，直接推到「但你还缺一层协作」的结论上。

### 2.3 FAQ（替换现有 6 条外贸问题）

1. **Agent 会不会乱改我的代码？** —— 每个任务一个独立工作目录，仓库按白名单放行，环境变量做过滤；关键动作仍由你审批。
2. **我在用 Claude Code，能用吗？** —— 不只 Claude Code。本地 daemon 会自动探测你机器上已经装好的 CLI，14 种都支持，不绑定任何一家。
3. **代码会传到你们服务器吗？** —— Agent 在你自己的机器上跑，server 只负责调度和状态同步。也可以整体自托管。
4. **和 Cursor / Copilot 有什么区别？** —— 它们是「你在 IDE 里用一个 AI」；这里是「让 AI 成为团队里能接活的成员」，并且团队所有人都看得见。
5. **我们只有 5 个人，用得上吗？** —— 这正是设计目标。Squads 的稳定路由、Autopilot 的定时活、Skill 的经验沉淀，都是为「人少事多」准备的。
6. **怎么开始？** —— 装 CLI → 登录工作区 → 本机起一个 daemon → 把第一个 issue 指派给 agent。

## 8. 验收断言

改完之后逐条验证：

1. 打开 `/`，首屏 H1 不含 "overseas / buyer / signal / quote" 任一词
